# Plan 027: Make the French report read like consulting prose, not a filled template

## Status

- **Priority**: P1
- **Effort**: M
- **Risk**: MEDIUM (one step touches report pagination; see step 5)
- **Depends on**: 018, 019, 025
- **Category**: LLM writing pass, report copy
- **Planned at**: commit `823c4d9` on `main`, 2026-09-07

## Why this matters

The operator read the French report and found the wording odd, sometimes
unlike anything a person would write, sometimes not professional. Measured
against the two most recent stored French analyses, the complaint is precise
and it is not a grammar problem. The prose is grammatical. It repeats.

| Pattern | www.briketenia.com | www.villasfoch.fr |
| --- | --- | --- |
| Actions opening `Demandez à votre prestataire technique` | 18 / 18 | 18 / 18 |
| Actions carrying the `..., afin de ...` benefit clause | 12 / 18 | 15 / 18 |
| Business impacts opening `Ces constats` / `Les constats` | 5 / 6 | 5 / 6 |
| Business impacts exactly two sentences long | 6 / 6 | 6 / 6 |

Eighteen consecutive recommendations opening with the identical seven-word
phrase is not a tone failure, it is the template showing through. A client
reads three of them and understands that nobody wrote this.

Worse, the executive summary's closing sentence is being copied verbatim out
of the prompt. `packages/llm/src/writing-prompt.ts` line 73 offers
"Pris ensemble, ces constats appellent une correction méthodique de votre
site, à commencer par les thèmes que ce rapport classe en premier" as a
preferred example, and the 2026-09-04 Briketenia analysis closes on that exact
sentence, word for word. Every French report now ends identically, on the one
sentence the client is most likely to reread. That regression was introduced
by the fix for issue #55, which replaced a bad sentence with a canned one.

Three causes, only one of which is a style problem:

1. **The rules mandate the repetition.** The prompt requires the exact same
   provider phrase in every action of every theme, so that a client never
   reads "votre prestataire technique" in one priority and "votre agence" in
   the next and infers two parties. The reasoning is sound. The consequence,
   uniform openings eighteen times over, was not anticipated. The
   finding-noun rule does the same to `businessImpact`.
2. **The caps forbid consulting length.** `businessImpact` is capped at two
   sentences and rejected above it; `recommendedActions` at three entries.
   Every impact paragraph is exactly two sentences because two is the
   ceiling.
3. **The prompt is a stack of prohibitions with no positive model.** Ten
   appended notes, nearly all of the form "never write X, responses
   containing X are rejected". Nothing describes what good French consulting
   prose reads like. The model is told precisely what to avoid and nothing to
   aim for, then run at temperature 0.2 with `reasoning_effort: 'none'`, so
   it returns the safest sentence that clears every guard.

## Current state

- `packages/llm/src/writing-prompt.ts` (135 lines) builds one English system
  prompt for both languages, with French guidance embedded as `prefer X over
  Y` pairs inside otherwise English notes. `LANGUAGE_INSTRUCTION` (line 11)
  is the only per-language branch.
- The provider-phrase mandate and the "never switch to votre agence" rule are
  inside the `recommendedActions` bullet of the base prompt, not in a named
  note constant.
- `executiveSummaryClosingNote` (line 73) carries the verbatim-copied French
  sentence and its English twin.
- `packages/llm/src/writing-schema.ts` lines 4-5 hold both caps:
  `MAX_BUSINESS_IMPACT_SENTENCES = 2`, `MAX_RECOMMENDED_ACTIONS = 3`. The
  sentence cap is a Zod `.refine`; the action cap is `.max()`.
- Themes render as a plain `<ul>` with no fixed height
  (`packages/report/src/template/sections/themes.ts:489`), but
  `.theme-card` carries `break-inside: avoid`
  (`packages/report/src/styles/paged.css:214-218`). Longer prose therefore
  interacts directly with trade-off 17.
- `packages/llm/src/lint-stored-analyses.ts` already walks stored analyses,
  never rejects anything, and always exits 0. It is the natural home for a
  repetition measurement that does not gate.
- French and English are generated by two independent writing passes over one
  shared structure document. Neither is a translation of the other, so this
  plan changes French quality without touching the English pair's provenance
  beyond the shared prompt builder.

## Scope

In scope: levers A, B, and C from the 2026-09-07 discussion, plus the two
cheap adjacent ones (G, H) that live in the same file and the same tests, plus
the non-gating measurement (I).

- **A. Vary the mandated phrasings.** Replace the single required provider
  phrase with a small approved set of French formulations that all name the
  same party, enforced as set membership rather than string equality. Same for
  the `afin de` benefit clause: stop implying one syntax.
- **B. Raise the length caps.** `businessImpact` to five sentences,
  `recommendedActions` to five entries, with a floor as well as a ceiling so
  the model does not simply keep writing two.
- **C. A French register document and reference corpus.** New
  `docs/rules/report-writing-style.md`, written in French for the French
  pass, carrying the register, the sentence-structure rule currently buried in
  `sentenceStructureNote`, and three to four fully worked example themes.
  Replaces the scattered `prefer X over Y` pairs.
- **G. Raise the writing pass's temperature above 0.2.** The determinism
  argument in `constants.ts` is about repeatable priorities, and priorities
  come from the structure pass. Prose has no repeatability requirement, and
  0.2 is what makes verbatim example-copying likely.
- **H. Write the French system prompt in French.** English instructions
  produce calque syntax in French output.
- **I. Measure repetition without gating it.** Extend
  `lint-stored-analyses.ts` to report identical action openings, identical
  impact openings, and any output sentence matching a prompt example.

Out of scope, deliberately:

- **D, promoting the shadow reviewer to a register gate.** See "Rejected"
  below.
- **E, raising `reasoning_effort` above `none`**, and **F, feeding the writer
  real business facts**. Both are promising and both need an operator
  decision first; recorded under "Open decisions".
- Any change to the structure pass, to priorities, to `llm-output.ts`, or to
  any locked contract. Nothing here lets the model introduce a finding.

## Open decisions, for the operator

**E. Raise `reasoning_effort` for the writing pass.** All three passes run at
`'none'` (`packages/llm/src/client.ts:86,180,258`). The writing pass is the
only genuinely generative one, and it is running at the same zero-thinking
setting as two passes that mostly echo structure. Raising it for the writing
pass alone is the single highest-leverage knob left. It is not blocked by
trade-off 67, which forbids splitting *models* per pass, but persisted
analyses record only `model` and `temperature`, so a per-pass effort would
need a provenance field to stay honest. Cost per report rises.

**F. Give the writer real business facts.** Today `siteContext` is four thin
fields, and on both rehearsal runs it was absent entirely, so the model wrote
from `businessType: 'unknown (no intake context provided)'`. It does not know
it is describing a three-star hotel with twenty-five rooms in La Tremblade,
because nothing tells it, even though the catalogue holds every one of those
facts deterministically. This is probably a larger quality lever than
everything in this plan combined, and it is deterministic, so it carries no
non-negotiable-rule-1 risk. It is out of scope here because it spans `core`,
`interface`, and the intake path, and deserves its own plan.

## Steps

### Step 1: Write the French register document

Create `docs/rules/report-writing-style.md`. Written in French. It carries the
register, the subject-verb-complement rule (moved out of
`sentenceStructureNote`), an explicit instruction to vary sentence openings
across themes, and three to four fully worked example themes in the target
register, each with a *different* structure.

**Verify**: no example sentence in the document is one the current prompt
already offers, so a verbatim copy is detectable as new.

### Step 2: Restructure the writing prompt around the document

Rewrite `buildWritingSystemPrompt` so the French branch emits a French prompt
(H) whose positive half is the register document's substance and whose
negative half is the existing guard-mirroring notes, unchanged in meaning.
Replace `executiveSummaryClosingNote`'s single canned sentence with three
varied ones and an instruction to write a closing sentence, not to pick one.

Keep every guard-mirroring note pointing at the same source of truth it does
today (`SEVERITY_VOCABULARY`, `BANNED_SEVERITY_SYNONYMS`,
`FINDING_NOUN_VOCABULARY`, `REQUIRED_WCAG_VERSION`,
`BUSINESS_CLAIM_EXAMPLES`). No guard changes meaning in this plan.

**Verify**: `writing-prompt.test.ts` passes with assertions updated to the new
shape; every existing guard test is untouched and green.

### Step 3: Allow varied provider phrasings (A)

Introduce an approved ordered set of French formulations naming the technical
provider, and the English equivalents. Enforce set membership where the prompt
previously demanded one string. The "two parties" risk stays closed because
every member names the same party.

**Verify**: a new test asserts every approved phrase names the provider and
that no approved phrase introduces a second party noun (`agence`, `équipe
interne`, `développeur`).

### Step 4: Raise the length caps and add floors (B)

`MAX_BUSINESS_IMPACT_SENTENCES` 2 to 5, with a floor of 3.
`MAX_RECOMMENDED_ACTIONS` 3 to 5, with `.min(2)`. Update the prompt's stated
limits from the same constants, never a second copy.

**Verify**: `writing-schema.test.ts` covers both new bounds at their edges.

### Step 5: Prove longer themes still paginate

`.theme-card` is `break-inside: avoid`. Trade-off 17 records what happens when
an unbounded group is forced onto one page, and the Lagnonu incident in
`paged.css:338-360` records Paged.js hitting its own repeated-layout guard at
a boundary it could not resolve. Longer prose makes both more likely.

Render the report from `packages/report/src/stress-fixture.ts` with themes at
the new maxima (5 sentences, 5 actions, longest approved provider phrase) and
confirm the PDF generates without the repeated-layout guard firing and without
a theme card overflowing its page.

**STOP** if a theme card can exceed a page at the new maxima. Do not remove
`.theme-card`'s `break-inside: avoid` to make this pass; report it and stop.
Bounding a card's rendered height is exactly the mechanism trade-off 17 says
does not exist yet.

### Step 6: Measure repetition without gating it (I)

Extend `lint-stored-analyses.ts` with three reported metrics per analysis:
share of actions sharing their opening five words, share of impacts sharing
their opening two words, and any output sentence matching a prompt example
verbatim. Reports, never rejects, still exits 0.

**Verify**: run it over the two stored French analyses and confirm it
reproduces the table in "Why this matters", including the verbatim-close hit
on Briketenia.

### Step 7: Regenerate and read as the client

Regenerate the French analysis for both stored audits (standing-authorized per
CLAUDE.md "Analysis and PDF authorization") and re-run step 6's lint.

**Done when**: no opening phrase is shared by more than half the actions, no
output sentence matches a prompt example verbatim, and the operator has read
the French PDF end to end and accepts the register. The operator's reading is
the gate, not the lint.

## Test plan

- `packages/llm`: `writing-prompt.test.ts`, `writing-schema.test.ts`,
  `typography.test.ts`, plus every guard test unchanged and green.
- `packages/report`: `pdf.test.ts` and the stress render from step 5.
- Full `pnpm run check` before handoff.
- No test calls a live model API. Step 7 is a manual operator step.

## Risks

- **Longer prose breaking pagination.** Step 5 exists for this and stops
  rather than working around it.
- **A richer reference corpus increasing verbatim copying.** This is the
  defect the plan is fixing, so the corpus must offer several varied examples
  per field, never one canonical sentence, and step 6 measures whether it
  worked.
- **Raising temperature moving priorities.** It cannot: priorities come from
  the structure pass, which this plan does not touch. Restrict the change to
  the writing call.

## STOP conditions

- A theme card can exceed one page at the new maxima (step 5).
- Any change would touch `findings.ts`, `severity.ts`, or `llm-output.ts`.
- Any guard's meaning would have to weaken to let the new prose through.
  A guard that now rejects good prose is a finding to report, not a rule to
  lower.

## Rejected: promoting the shadow reviewer to a register gate (lever D)

Rejected on four grounds, the first two decisive:

1. It asks the same weak model to grade its own taste. The reviewer is
   another `gpt-5.4-mini` call at `reasoning_effort: 'none'`.
2. A wrong rejection makes the writing worse, not better. Every rejection
   feeds `buildWritingRetryFeedback` and pushes the model toward the safest
   phrasing that passes, which is the disease this plan is treating. Issue #21
   already measured that dynamic: eight consecutive French rejections for one
   word.
3. Style has no rejectable definition. The existing guards work because they
   test mechanical facts: a digit, a banned word, a version number.
   "Professional" is not one.
4. Trade-off 55 already records the reviewer as not promotable on the current
   model, having flagged correct generic commercial consequences as
   unsupported.

Step 6 keeps the useful half, measurement, and drops the harmful half, the
gate.
